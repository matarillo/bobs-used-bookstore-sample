# R4 — 店の調子を数字で知る（4 件 / 8 pt ＋ 条件付き 2 件 / 5 pt）

局面は **開発後期**。主題は「どれだけの品質で足りるか」と「数字を信じられるか」に移る。
受け入れ基準は **数値と測り方をセットで**書き、**回帰**を明示的に 1 項目持つ
（[acceptance-criteria.md §4](../policies/acceptance-criteria.md)）。

`PBI-042` と `PBI-043` は **条件付き**である。[phases.md §4](../policies/phases.md) の条件——
実運用の数字が要求し始めたこと——を起票時に確認し、**要求していなければ捨てる**。
だから[プロダクトバックログ](../product-backlog.md)の必須の合計には数えない。

## PBI-039 — 【店】手入力の本にも原価を記録できる

| 項目 | 内容 |
| --- | --- |
| 種別 | 実装 |
| STORY- | STORY-17 |
| サイズ | M |
| 依存 | PBI-006 |
| 由来 | **粗利の過小評価に基づく誤った仕入・値付け判断のリスク**（`PBI-004` で残置とした問い） |

**なぜダッシュボードより先か**: 原価を持たない書籍は粗利の計算から除外される。
**この穴を塞がずに数字を出すと、店主は過小な粗利を見て値付けを誤る。**
数字を出す前に、数字の材料を揃える。

**受け入れ基準**

- [ ] `PBI-004` で残置とした「原価をいつ誰が入れるのか」に回答が出て、
      手入力の書籍に仕入原価を入力できる。**入力を必須にするかどうか**が合意どおりになっている（自動）
- [ ] [`RULE-BOOK-01`] 原価が未知の書籍は、粗利見込が **0 ではなく未定義**として扱われる（自動）
- [ ] [`RULE-SALES-03/04`] 原価が未知の売上が粗利の計算から除外され、
      **利益として数えられない**（自動 / `SPEC-SERVICE`）
- [ ] [測定] 原価が未知の在庫の**比率**が店に見える。リスクの監視列がこの数字に置き換わる（手動）
- [ ] [回帰] `SPEC-BOOK` / `SPEC-ORDER` の自動テストが全て通る（自動）

## PBI-042 — 取引記録を失わない【条件付き】

| 項目 | 内容 |
| --- | --- |
| 種別 | 実装 |
| STORY- | —（横断） |
| サイズ | L |
| 依存 | PBI-010 |
| 由来 | データ喪失のリスク、`NFR-DATA-01` の昇格 |

**起票の条件**: 買取・注文の取引量が増え、**データ喪失のリスクのトリガが引かれたとき**に着手する。
引かれていなければ、コスト上限との交換（[tradeoffs §3](../../docs/product/tradeoffs.md)）を
維持して**この PBI は捨てる**。

**PBI-010 との関係**: `PBI-010` は「障害時にどこまで失うかを PO が受容した」ところで終わっている。
ここはその受容を**買い直す** PBI である。スキーマの更新で既存データを消さないことは
`PBI-003` が既に満たしているため、ここで扱うのはバックアップと復旧だけである。

**受け入れ基準**

- [ ] [`NFR-DATA-01`] 状況「障害が起きた」→ 応答「合意した目標時点まで戻せる」
      → 測定「復旧の実演を PO 立ち会いで 1 回行い、所要時間を記録した」（手動）
- [ ] 目標時点と目標復旧時間が、実測をもとに PO と合意され、`NFR-` に書かれている（読み合わせ）
- [ ] [回帰] 復旧したデータの上で `SPEC-ORDER` / `SPEC-OFFER` / `SPEC-BOOK` の
      自動テストが全て通る（自動）
- [ ] バックアップが無効化されたことを検知できる（自動または日次の監査項目）（自動）
- [ ] リスク台帳の監視列が「バックアップ成否の日次確認」に置き換わり、
      `NFR-DATA-01` が `[規定しない]` から `[強制]` に昇格している（読み合わせ）
- [ ] 増えた費用が PO に提示され、コスト上限が再交渉されている（読み合わせ）

## PBI-043 — 主要画面の応答を測り、基準に入れる【条件付き】

| 項目 | 内容 |
| --- | --- |
| 種別 | 実装 |
| STORY- | —（横断） |
| サイズ | M |
| 依存 | PBI-040 |
| 由来 | `NFR-PERF-01` の昇格 |

**起票の条件**: 応答時間の水準は規定していない。着手するのは、**遅いという声が実際に出たとき**である。

**測ってから決める。** 思いつきの数値を `[強制]` にしない
（[acceptance-criteria.md §4.2](../policies/acceptance-criteria.md)）。
[splitting.md E2](../policies/splitting.md) のとおり、**測る**と**満たす**は分けてよい——
測って十分なら、満たす側は捨てる。

**受け入れ基準**

- [ ] [測る] 検索・在庫一覧・注文一覧・ダッシュボードの応答時間を、
      [constraints](../../docs/product/constraints.md) の想定規模で実測し、分布を記録した（自動）
- [ ] [決める] 実測値をもとに `NFR-PERF-01` の「状況 → 応答 → 測定」が書かれ、
      顧客 PO と合意されている。**十分だったなら規定しないまま据え置き、
      その判断を `ADR-` に残す**（読み合わせ）
- [ ] [`[強制]` にした場合] その水準を固定する自動テストがあり、超えたら CI が赤になる（自動）
- [ ] [回帰] 性能のために加えた変更が振る舞いを変えていないことが、
      既存の `SPEC-` の自動テストで確かめられる（自動）
