# R2 — 注文と配送先を自分で整えられる（PBI-023〜029）

局面は **開発中期**。1 PBI = 1 垂直スライスであり、合意は PBI の中に含まれる
（[splitting.md §2](../policies/splitting.md)）。
受け入れ基準は **ユーザーが観測できる振る舞いだけ**を書き、層・置き場は書かない
（[acceptance-criteria.md §3](../policies/acceptance-criteria.md)）。

> **ここに書いてある基準は、読み合わせに持ち込む案である。**
> 中期は仕様の合意が PBI の中にあるため、`Q-` の回答しだいで基準の文言が変わる。
> スプリント前半の読み合わせで確定させ、確定した文言でスプリントを終える。

## PBI-024 — 注文を取り消せる

| 項目 | 内容 |
| --- | --- |
| 種別 | 実装 |
| STORY- | STORY-09 |
| サイズ | M |
| 依存 | PBI-023 |
| UC- | `UC-CUST-20` |
| 読み合わせる `Q-` | **`Q-08`（注文の取消をどう扱うか、優先度 A）** |

**なぜ M か**: 取消は在庫を戻す。**金と在庫が同時に動く数少ない顧客操作**であり、
現行は「状態にかかわらずボタンが出て、押した瞬間に取り消され、失敗するとエラー画面に落ちる」
（`Q-08`）。この三つをどう変えるかを PBI の中で合意する。

**受け入れ基準**

- [ ] [`UC-CUST-20`] 受付待ち・受付済の注文を取り消すと、状態が取消済になる（自動 / `SPEC-ORDER`）
- [ ] [`RULE-STOCK-02`] 取消が成立したとき、各明細の数量が在庫に戻る。
      **成立しなかったときは戻らない**（自動）
- [ ] [`RULE-SERVICE-05`] 取消はべき等である——同じ注文をもう一度取り消しても
      エラー画面に落ちない（自動）
- [ ] [`Q-08` の回答] 取り消せない注文（出荷済・配達済・取消済）に対する見せ方が、
      合意したとおりになっている（手動）
- [ ] [`RULE-ACCESS-01`] 他人の注文番号を指定しても取り消されず、その旨が伝わる（自動）
- [ ] 取消の前に確認を挟み、取り消せたことが画面で分かる（手動）

## PBI-028 — 同時操作の競合をその場で伝える

| 項目 | 内容 |
| --- | --- |
| 種別 | 実装 |
| STORY- | —（横断） |
| サイズ | M |
| 依存 | PBI-024 |
| 読み合わせる `Q-` | **`Q-07`（業務上の失敗をどう伝えるか、優先度 A）の適用** |

**なぜ要るか**: 線引きは `PBI-002` で決めた。ここで**実際に画面へ適用する**。
現場が日常的に踏むのは同時操作の競合であり、
「エラー画面に落ちて理由が伝わらない」ままでは運用できない（`Q-07`）。

**受け入れ基準**

- [ ] 出荷済になった注文を顧客が取り消そうとしたとき、理由がその場で伝わる（手動）
- [ ] 別のスタッフが先に処理した注文を操作したとき、理由がその場で伝わり、
      **最新の状態が画面に出る**（手動）
- [ ] [`RULE-SERVICE-03`] 個別に指定した対象が不在のときは失敗し、
      [`RULE-SERVICE-04`] 対象を個別に指定しない操作は不在でも成功する（自動）
- [ ] `PBI-002` で「エラー画面に落とす」と決めた失敗は、**そのままエラー画面に落ちる**（手動）
- [ ] 上の振る舞いを固定する自動テストがあり、退行が検知できる（自動）

## PBI-029 — 増えた一覧の並び順とページ送りを揃える

| 項目 | 内容 |
| --- | --- |
| 種別 | 実装 |
| STORY- | —（横断） |
| サイズ | M |
| 依存 | PBI-023, PBI-025, PBI-026 |
| 読み合わせる `Q-` | `Q-09`（件数が増えた一覧をどうするか）、`Q-12`（空の一覧の見せ方） |

**なぜここか**: R2 で顧客が**自分の履歴を見る**ようになって初めて、件数が問題になる。
R1 までは一覧が短く、誰も困らない。

**受け入れ基準**

- [ ] [`Q-09` の回答] 自分の注文・自分の住所・かご・欲しい物の一覧に、
      合意した並び順が適用されている（自動）
- [ ] [`Q-09` の回答] 合意した件数を超えたときの見せ方（ページ送り等）が適用されている（自動）
- [ ] 100 件を超える注文を持つ顧客でも、一覧から目的の注文にたどり着ける（手動）
- [ ] [`Q-12` の回答] 空の一覧の文言と誘導が、すべての一覧で揃っている（手動）
