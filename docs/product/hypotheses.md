# 仮説台帳（Hypotheses）

要求層は事実ではなく仮説から始まる。この台帳は仮説を一覧し、検証を通じて
`vision` / `goals` / `actors` / `spec` の `RULE-` を「形にしていく」ためにある。
**仮説を立て・実証・反証する流れは [product/README §3](README.md) が定める。ここでは繰り返さない。**

## 台帳の枠 — リーンキャンバス

枠の取り方は **リーンキャンバス** に倣う。リーンキャンバスは、事業アイデアを九つの枠で
一枚に収め、どこが最も危うい前提かを一望できるようにする仮説整理法である。
各枠の意味と、実証されたときに本体を移す先は次のとおり。

- **顧客の課題** — 解くべき痛みは何か → `goals`
- **顧客セグメント** — その痛みを抱えるのは誰か → `actors`
- **価値提案** — なぜ自分たちが選ばれるか → `vision`
- **ソリューション** — その課題をどう解くか → `story-map` / `UC-`
- **主要指標** — 成否を何で測るか → `goals`
- **チャネル** — どう顧客へ届けるか → 事業背景（実装は消費しない）
- **収益の流れ** — どう対価を得るか → 事業背景
- **コスト構造** — 何に費用がかかるか → 事業背景
- **圧倒的な優位性** — 容易に真似されない理由 → 事業背景

生のキャンバスを唯一の正にしない。実証された枠の蒸留物だけを上記の層へ移し、
ここには要約と参照を残す（同じ事実を二か所に書かない／[文書体系 §6.1](../README.md)）。
「事業背景」の四枠は文脈として持つが、コード生成の入力にはしない。

## 状態

各 `HYP-` は次のいずれかを持つ。状態を進めたときにすること（昇格・撤回）は
[product/README §3](README.md)。

- **仮説** — まだ検証していない
- **検証中** — 検証の最中
- **実証** — 支持された
- **反証** — 覆った

## 台帳

各行は検証方法を必ず持つ。反証可能な仮説と検証方法があることが、要求層で
合意できることの条件だからである（[文書体系 §1.2](../README.md)）。
