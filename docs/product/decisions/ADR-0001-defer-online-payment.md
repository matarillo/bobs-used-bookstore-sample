# ADR-0001 — R1(MVP) ではオンライン決済を持たず、代金の授受をシステムの外に置く

| 項目 | 内容 |
| --- | --- |
| 対象 | STORY-19 / Q-28 / EPIC-CHECKOUT |
| 決めた人 | 店主（プロダクトオーナー） |
| 影響する文書 | [vision.md 非ゴール](../vision.md)、[story-map.md §5.1](../story-map.md)、[integrations.md §4](../../spec/integrations.md)、[goals.md §3](../goals.md) |

## 決めたこと

注文の確定に決済を伴わせない。金額は算出して見せるが、支払われた事実はシステムに記録しない。
代金の授受は、店が実店舗で使ってきた運用（請求・振込・店頭受け渡し）でまかなう。

## そう決めた理由

- MVP で検証したいのは「店の外の読者が本を探し、注文するか」（HYP-01, HYP-06）であり、
  支払手段は検証対象ではない。既存の運用で代替できるものに MVP の工数を使わない。
- 決済代行の契約・審査・手数料は、注文が立つと分かる前に負うには重い固定費である。
- スコープを先に譲るという方針（[tradeoffs §1](../tradeoffs.md)）の最初の適用である。

## 採らなかった案とその理由

| 案 | 採らなかった理由 |
| --- | --- |
| 決済代行（カード決済）を MVP に含める | 契約と実装の両方が重く、MVP の便を 1 つ遅らせる見積りになった。検証したい仮説に寄与しない |
| 「支払済」フラグだけ先に設ける | 決済の裏付けなく手で立てるフラグは、店頭の帳簿と二重管理になり、かえって齟齬を生む |

**再訪の条件**: 未収・支払齟齬のトラブルが常態化したとき（[RISK-02](../risks.md)）。
その際は決済の導入と併せて「支払の記録」をドメインに持ち込むかを決める（[Q-28](../open-questions.md)）。
