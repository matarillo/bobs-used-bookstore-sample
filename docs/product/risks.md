# プロダクトリスク台帳

**顧客（プロダクトオーナー）が判断・受容するリスクだけ** をここに置く。
技術・スケジュール・コスト・リソースのリスクは docs/ に置かず、プロジェクト管理側で扱う
（バックログを docs/ に置かないのと同じ理由／README の思想）。

## まず分解する

規制・セキュリティは「リスク」のまま放置せず、次のいずれかへ **分解** する。

| 分解先 | 例 |
| --- | --- |
| `spec/rules.md`（`RULE-`） | 顧客が決める閾値・手順 |
| `design`（`INV-`） | 破れてはならない不変 |
| `spec/non-functional.md`（`NFR-`） | 満たすべき品質水準（観測・テスト可能） |
| `constraints.md` | 前提として受け入れるもの |

分解してもなお残る「**監視するしかない不確実性**」だけを `RISK-` として採番する。

## 早期アジャイルの最大リスク

汎用カテゴリには無いが、初期の最大のプロダクトリスクは **中核仮説が外れること** である。
その種の `RISK-` は必ず `HYP-` と `Q-` に結び付ける。
