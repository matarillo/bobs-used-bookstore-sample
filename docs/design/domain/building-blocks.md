# 共通構成要素

集約に先立って、ドメイン全体で共有される構成要素を定義する。
特に**値オブジェクト**は、このモデルにおける不変条件の相当部分を担っている。

## 1. エンティティ基底

すべての永続化されるエンティティが共通に持つ属性。

| 属性 | 論理型 | 要否 | 意味 |
| --- | --- | --- | --- |
| 識別子 | 識別子 | ● | 集約インスタンスを一意に指す。未採番は 0 |
| 作成者 | テキスト | ● | 既定値 "System" |
| 作成日時 | 日時 | ● | 生成時の UTC |
| 更新日時 | 日時 | ● | 生成時の UTC。以後の更新は呼び出し側の責務 |
| 行バージョン | 内部 | ▲ | 楽観的並行制御のためのトークン。永続化前は意味を持たない |

**派生**

| 名称 | 定義 |
| --- | --- |
| 新規エンティティか | 識別子が 0 であること |

> **設計上の注意**: 作成日時・更新日時は業務的な日付ではなく**技術的な記録**である。にもかかわらず
> 読み取りモデルの「今月の注文数」等は作成日時に依存している（[ISSUE-11](../issues.md)）。

## 2. VO-MONEY — 金額

**「金額」は単なる数ではない**という主張を型として表明したもの。売価・買取価格・小計・税・合計は
すべて同じ種類のものであり、その種類には数にはない性質がある。

### 2.1 定義

| 性質 | 値 |
| --- | --- |
| 通貨 | USD（単一通貨。二通貨を扱うことになればこの前提が破れる） |
| 小数桁 | 2（店が実際に請求・支払できる最小単位） |
| 丸め | 四捨五入（絶対値を大きくする方向） |
| 符号 | **非負のみ** |
| 等価性 | 金額が等しければ等しい（値としての同一性） |

### 2.2 生成

| 操作 | 規則 |
| --- | --- |
| `Of(数)` | 負値なら**拒否**。非負なら通貨最小単位に丸めて生成 |
| `OfNullable(数?)` | 未設定なら未設定のまま。設定済なら `Of` と同じ |
| `Zero` | 0 の金額 |

**妥当性は生成時に確定する**。したがって金額を受け取った側は改めて検査する必要がない。

### 2.3 演算

| 演算 | 結果型 | 意味 |
| --- | --- | --- |
| 金額 ＋ 金額 | 金額 | 合算 |
| 金額 × 数量 | 金額 | 「1冊の値段を何冊分か取る」。可換 |
| 金額.Times(率) | 金額 | 按分（税など）。負の率は**拒否**。結果は丸められ、それ自体が請求可能 |
| 金額.Less(金額) | **差額** | 差。**金額ではない**——店が仕入値より安く売ることは実際に起こりうるため、負値を表現できなければならない |
| 比較 (< > <= >=) | 真偽 | 大小比較 |
| 合計 (Sum) | 金額 | 列の総和。金額のまま合算し、途中で数に落とさない |

> **`Less` が金額を返さない理由**は重要である。「差」を金額として扱ってしまうと、
> 損失が表現できなくなるか、非負制約が破れるかのどちらかになる。粗利・粗利見込がすべて
> **差額**であるのはこのためである。

### 2.4 適用範囲

| 適用される | 適用されない |
| --- | --- |
| 書籍の売価・仕入原価 | 統計値（読み取りモデルの投影） |
| オファーの買取価格 | 粗利・粗利見込（差額であるため） |
| 注文明細の価格・原価 | |
| 小計・税・合計 | |

統計値が金額でないのは、それが**永続化層が算出した投影**であり、この型が担う不変条件の
対象ではないためである（[読み取りモデル](read-models.md)）。

## 3. VO-QUANTITY — 数量

書籍の冊数。二つの異なる規則が適用されるため、**生成手段が二つある**。

### 3.1 定義

| 性質 | 値 |
| --- | --- |
| 値域 | 非負整数 |
| 等価性 | 値が等しければ等しい |

### 3.2 生成

| 操作 | 規則 | 用途 |
| --- | --- | --- |
| `Of(数)` | 負値を**拒否**。0 を許す | **在庫数**。空の棚は正当な在庫水準である |
| `OfAtLeastOne(数)` | 1 未満を**拒否** | **明細の数量**。0冊を指す行は行ではない |
| `None` | 0 | |
| `One` | 1 | |

「何を数えているか」によって適用される規則が違うため、生成手段が分かれている。

### 3.3 演算

| 演算 | 結果型 | 意味 |
| --- | --- | --- |
| 数量 ＋ 数量 | 数量 | 増加 |
| 数量 − 数量 | 数量 | 減少。**結果が負になる場合は拒否**（在庫不足が0に飽和して隠れることを防ぐ） |
| 比較 (< > <= >=) | 真偽 | 大小比較 |

## 4. VO-CLASSIFICATION — 分類

書籍と買取オファーが分類される4軸の組。

### 4.1 構造

| 軸 | 参照先の種別 |
| --- | --- |
| 出版社 | Publisher |
| 書籍種別 | BookType |
| ジャンル | Genre |
| 状態 | Condition |

4軸すべてが単一の参照データ項目群から供給されるため、**識別子だけでは出版社とジャンルを
区別できない**。この型は、その区別を生成時に強制するために存在する。

### 4.2 生成

| 操作 | 規則 | 用途 |
| --- | --- | --- |
| `Of(参照データ, 4つの識別子)` | 各識別子が**実在**し、かつ**その位置が要求する種別である**ことを検査。いずれかが破れれば拒否 | 外部（フォーム入力）からの生成 |
| 検査済としての生成 | 検査を行わない（内部専用） | すでに検査済の分類を持ち回るとき（オファー → 書籍の棚入れ、永続化からの復元） |

**INV-CLASS-01 [強制]**: 分類の各軸は、その位置が要求する種別の実在する参照データ項目でなければならない。

拒否時の理由は二つに区別される。

| 状況 | 意味 |
| --- | --- |
| 項目が存在しない | 指定された識別子の参照データ項目が見つからない |
| 種別が一致しない | 項目は存在するが、要求される軸とは別の種別である |

## 5. IUnitOfWork — 単位作業

**一度にまとめて確定される変更の範囲**を、名前のある概念にしたもの。

| 操作 | 意味 |
| --- | --- |
| 完了する | 前回の完了以降に任意のリポジトリを通じて行われた変更をすべて確定する |

ドメインサービスは単位作業を受け取り、自らそれを完了させる。これにより
**「どの変更が同一の原子的操作に含まれるか」が読み手に見える**。
具体的な境界は [ドメイン全体像](overview.md) §8 を参照。

## 6. PagedResult — ページ化された結果

読み取り側が返す、範囲を切り出した結果の集合。**ドメインが頁について言うべきことのすべて**であり、
それ以上ではない。

| 属性 | 論理型 | 意味 |
| --- | --- | --- |
| 要素 | 読み取り専用の列 | 切り出された行 |
| 頁番号 | 数 | **1始まり** |
| 頁サイズ | 数 | **要求された範囲の大きさ**。返ってきた行数ではない（最終頁は通常より短い） |
| 総件数 | 数 | 範囲を無視した、絞り込み条件に合致する行数 |

**派生操作**

| 操作 | 意味 |
| --- | --- |
| 写像 (Map) | 頁の情報を保ったまま、各要素を別の表現に変換する |

> 「次頁があるか」「何頁あるか」「頁送りにどのボタンを描くか」は**業務概念ではない**ため、
> 意図的に含まれていない。それらは画面を描く側の問いである。

## 7. DomainException — ドメイン例外

不変条件を破る操作が試みられたときに発生する。

| 発生させる状況 | 例 |
| --- | --- |
| 値の生成規則違反 | 負の金額、負の数量、0冊の明細 |
| 分類の検証失敗 | 存在しない項目、種別の不一致 |
| 状態遷移の違反 | 出荷済の注文を取り消す、未支払のオファーを棚入れする |
| 在庫の不足 | 在庫を超える出庫 |
| 厳格な更新の対象不在 | 指定された明細・住所・かごが存在しない |

## 8. 内部数値属性について

金額・数量は値オブジェクトだが、永続化と読み取り側（並べ替え・絞り込み・集計）は
**素の数**を必要とする。そのため各集約は、値オブジェクトの背後にある数を
**内部属性 (▲)** として保持している。

| 集約 | 内部属性 | 背後の値 |
| --- | --- | --- |
| AGG-BOOK | 売価の数、在庫数の数、仕入原価の数 | 売価、在庫数、仕入原価 |
| AGG-CART | 明細数量の数 | 明細の数量 |
| AGG-ORDER | 明細数量の数、価格の数、原価の数 | 明細の数量、価格、原価 |
| AGG-OFFER | 買取価格の数 | 買取価格 |

これらは**ドメインの公開面ではない**。読み込み時にも値オブジェクトの生成規則を通るため、
永続化された不正な値（例：0冊の明細）はここで拒否される。
