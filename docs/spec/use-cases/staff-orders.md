# スタッフ：注文を履行する

対象画面: [`SCR-A-ORDERS`](../wireframes/admin/SCR-A-ORDERS.html), [`SCR-A-ORDER`](../wireframes/admin/SCR-A-ORDER.html)
**管理者グループに属していること**が条件。[`SCR-A-ORDERS`](../wireframes/admin/SCR-A-ORDERS.html) は**管理画面を開いたときの既定画面**である。

> 在庫は**注文が確定した時点ですでに引き当てられている**。
> したがってこの章の操作は在庫を動かさない（[docs 11 OP-STAFF-12〜14](../../design/domain/operations.md)）。

## UC-STAFF-02 — 注文を一覧・絞り込む

| 項目 | 内容 |
| --- | --- |
| 由来 | [STORY-06](../../product/story-map.md) |
| アクター | 店舗スタッフ |
| 画面 | [`SCR-A-ORDERS`](../wireframes/admin/SCR-A-ORDERS.html) |
| ドメイン対応 | [OP-STAFF-15](../../design/domain/operations.md) / [RM-ORDER-LIST](../../design/domain/read-models.md) |
| 目的 | 今日出すべき荷物と、遅れている注文を見つける |

**【Boundary：画面】**

- 絞り込み条件:

  | 条件 | 入力の形 |
  | --- | --- |
  | 注文の状態 | 選択（すべて／受付待ち／受付済／出荷済／配達済／取消済／納期超過） |
  | 注文日 From | 日付 |
  | 注文日 To | 日付 |
  | 納期超過のみ | チェックボックス |

- 表示項目（注文ごと）: 顧客名、状態、注文日、納品予定日、**合計（税込）**、「詳細」
- **納期超過の注文には、納品予定日の隣に「納期超過」の印を付ける**
- ページ送りあり

**【Controller：手順】**

1. 絞り込み条件と頁番号を受け取る。
2. 条件に合う注文の頁を問い合わせる。
3. [`SCR-A-ORDERS`](../wireframes/admin/SCR-A-ORDERS.html) に渡して描画する。

**【Entity：ルール】**

- `AGG-ORDER`: [RULE-PERIOD-04](../rules.md)（**納期超過 ＝ 納品予定日を過ぎ、かつ配達済でも取消済でもない**）
- 納期超過は**注文集約が定めるルール**であり、一覧の絞り込みと注文自身の判定が**同じ答えを返すことが保証されている**
  （[docs 13 §3.3](../../design/domain/read-models.md)）。画面が独自に日付を比べているのではない
- [RULE-PERIOD-03](../rules.md): 納品予定日 ＝ 注文時点の 7 日後（**根拠のない定数**。[Q-29](../../product/open-questions.md)）
- **「注文日」という属性はドメインに存在しない**。記録の作成日時を注文日として扱っている（[ISSUE-11](../../design/issues.md)）

**【異常系】**

| 起きること | 画面の振る舞い |
| --- | --- |
| 取消済の注文 | 一覧に残る。絞り込みで分けられる |
| 該当が 0 件 | 空の表を描く（[Q-12](../../product/open-questions.md)） |

## UC-STAFF-03 — 注文の詳細を見る

| 項目 | 内容 |
| --- | --- |
| 由来 | [STORY-06](../../product/story-map.md) |
| アクター | 店舗スタッフ |
| 画面 | [`SCR-A-ORDER`](../wireframes/admin/SCR-A-ORDER.html) |
| ドメイン対応 | [OP-STAFF-15](../../design/domain/operations.md) |
| 目的 | 何を、どこへ、いくらで送るのかを確認する |

**【Boundary：画面】**

- 表示項目:

  | 区画 | 項目 |
  | --- | --- |
  | 配送先 | 顧客名、住所行1・2、市区町村、州、郵便番号、国 |
  | 注文の情報 | 状態、注文日、納品予定日、**小計・税・合計の 3 段**（顧客側の画面と異なり内訳が出る） |
  | 品物 | 書名、著者、出版社、ジャンル、書籍種別、コンディション、売価、数量、小計 |

- 操作: 状態に応じて 1 つだけ出る（下表）／「戻る」

  | 注文の状態 | 出る操作 |
  | --- | --- |
  | 受付待ち | 「受け付ける」 |
  | 受付済 | 「出荷する」 |
  | 出荷済 | 「配達済にする」 |
  | 配達済・取消済 | 操作なし |

- **取消の操作はない**（[Q-23](../../product/open-questions.md)）

**【Controller：手順】**

1. 注文識別子で注文を取得する（**絞り込みなし。スタッフ専用の照会**）。
2. [`SCR-A-ORDER`](../wireframes/admin/SCR-A-ORDER.html) に渡して描画する。

**【Entity：ルール】**

- [RULE-ACCESS-02](../rules.md): 絞り込みなしの単件照会はスタッフ専用
- `AGG-ORDER`: [RULE-ORDER-01〜04](../rules.md)（小計 → 税（10%）→ 合計）
- `AGG-ADDRESS`: [INV-ADDR-06](../../design/domain/invariants.md)（**顧客が住所を削除しても、この画面には注文時の配送先が出る**）

**【異常系】**

| 起きること | 画面の振る舞い |
| --- | --- |
| 存在しない注文番号 | エラー画面へ落ちる（[Q-07](../../product/open-questions.md)） |

## UC-STAFF-04〜06 — 注文の履行

3 つの操作は**同じ形**をしている。

| # | ユースケース | 操作名（画面） | 遷移元 | 遷移先 |
| --- | --- | --- | --- | --- |
| `UC-STAFF-04` | 受け付ける | 「受け付ける」 | 受付待ち | 受付済 |
| `UC-STAFF-05` | 出荷する | 「出荷する」 | 受付済 | 出荷済 |
| `UC-STAFF-06` | 配達完了を記録する | 「配達済にする」 | 出荷済 | 配達済 |

| 項目 | 内容 |
| --- | --- |
| 由来 | [STORY-06](../../product/story-map.md) |
| アクター | 店舗スタッフ |
| 画面 | [`SCR-A-ORDER`](../wireframes/admin/SCR-A-ORDER.html) |
| ドメイン対応 | [OP-STAFF-12〜14](../../design/domain/operations.md) |
| 目的 | 注文を受け、荷を作り、届いたことを記録する |

**【Boundary：画面】**

- 操作: 状態欄の隣のボタン。**確認ダイアログはない**
- フィードバック: **同じ注文詳細に戻り**、通知バナー（「受け付けました」「出荷しました」「配達済にしました」）
- 状態欄と操作ボタンが次の段のものに入れ替わる

**【Controller：手順】**

1. 対象の注文識別子を受け取る。
2. **注文に状態遷移を依頼する**（遷移できるかどうかの判断は集約が行う）。
3. 更新日時を記録する。
4. 単位作業を完了する。
5. **同じ注文の詳細画面**へ戻し、通知バナーを出す。

**【Entity：ルール】**

- `AGG-ORDER`: [INV-ORDER-03](../../design/domain/invariants.md)（**受付待ち → 受付済 → 出荷済 → 配達済 の順にのみ進む**。飛ばせない、戻せない）
- `AGG-ORDER`: [INV-ORDER-05](../../design/domain/invariants.md)（状態は集約の振る舞いを通じてのみ変わる）
- **在庫は動かない**。在庫は注文確定時に引き当て済みである（[RULE-STOCK-01](../rules.md)）
- [RULE-SALES-01](../rules.md): **取消済以外はすべて売上に計上される。**
  出荷前・受付前でも、注文が確定した時点で取引は成立している

> **「出荷済」は荷物を渡したことの記録であって、配送業者との連携ではない。**
> 追跡番号・配送業者・実際の出荷日を記録する項目はない（[Q-23](../../product/open-questions.md)）。

**【異常系】**

| 起きること | 画面の振る舞い |
| --- | --- |
| 別のスタッフが先に進めた注文を操作した | **失敗し、エラー画面へ落ちる**（[Q-07](../../product/open-questions.md)） |
| 顧客が同時に取り消した注文を出荷しようとした | 同上。**在庫の正しさは守られる**（取消済からは出荷できない） |
| 出荷を取り消したい | **できない。** 状態は戻せない（[Q-23](../../product/open-questions.md)） |
