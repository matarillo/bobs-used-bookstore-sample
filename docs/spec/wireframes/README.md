# ワイヤーフレーム

画面の**姿**を定める。1 画面 1 ファイルで、ファイル名は `SCR-` 識別子に一致させる。

| ここで定めるもの | ここで定めないもの |
| --- | --- |
| 要素の順序とグループ | どの項目・操作が必要か（[ユースケース](../use-cases/)の【Boundary】節） |
| 相対的な重み（何を大きく見せるか） | 必須・任意、入力の検証 |
| 画面内の領域の分け方 | 業務ルール（[rules.md](../rules.md)） |
| 状態によって版面がどう変わるか | 寸法・色・書体・余白 |

**項目の過不足はユースケース側で直す。ワイヤーフレーム側で足さない。**

## 1. ファイル

```
wireframes/
  README.md              本書
  customer/SCR-XXXX.md   店頭の画面
  admin/SCR-A-XXXX.md    管理の画面
```

1 枚が合意の単位である。「この画面はこれでよい」と業務担当者が言える大きさに保つ。

## 2. 1 枚の構成

```markdown
---
layer: spec
status: derived
derived-from: 4412aa1
---

# SCR-XXXX — 画面の名前

| 項目 | 内容 |
| --- | --- |
| 経路 | /path |
| 定めるユースケース | [UC-CUST-nn](../../use-cases/xxx.md) |
| フレーム | 店頭 / 管理 |

## 版面

（ASCII の版面。§3）

## 配置の意図

- なぜその順序・その重みなのか。**版面から読み取れないことだけ**を書く

## 状態による差分

（版面が状態で変わる場合のみ。§4）
```

**「定めるユースケース」以外に項目の説明を書かない。** 項目が何であるかはユースケースが定める。

## 3. 版面の描き方

### 3.1 ASCII で描く

コードフェンスの中に罫線で描く。図の生成器を使わない。

理由は差分の読みやすさである。テキストなので `git diff` に現れ、人も AI も直接編集でき、
どの環境でも同じに見える。

> [文書体系 §5.4](../../README.md) は「テキストから再生成できる図だけを保存する」と定めている。
> 版面はその意味の図ではない。**版面そのものが一次のテキスト**であり、他の何かの投影ではない。

幅は 72〜80 桁を目安に、枠を閉じる。

### 3.2 記法

| 記法 | 意味 |
| --- | --- |
| `[ 保存 ]` | ボタン |
| `▸ 詳細` | リンク |
| `[__________]` | 自由入力 |
| `[ 選択     v]` | 選択（ドロップダウン） |
| `( ) 未選択  (o) 選択` | ラジオ |
| `[ ] 未チェック  [x] チェック` | チェックボックス |
| `▨` | 画像 |
| `« ... »` | 同じ形の行が繰り返される |
| `‹ ... ›` | 条件付きで現れる要素。条件を中に書く |

繰り返しは**2 行書いて 3 行目を `«…»` で省く**。1 行だけでは繰り返しに見えない。

### 3.3 共通フレームは描かない

ヘッダと通知バナーは全画面で同じである（§6）。**各画面の版面は本文領域だけを描く。**
25 画面がヘッダを描き直すと、ヘッダを変えたとき 25 か所を直すことになる。

### 3.4 寸法は定めない

罫線の長さや空白の量に意味を持たせない。定めるのは**順序・グループ・相対的な重み**である。
「大きく見せる」ことは、囲みや見出しの階層で表す。

### 3.5 ラベルは用語集の日本語で書く

版面に書く文言は [用語集](../../glossary.md) の日本語を使う。

現行画面の英語表記をそのまま写さないのは、画面の言葉と用語集が食い違っている箇所があり、
どちらに揃えるかが未決だからである（[Q-22](../../product/open-questions.md)）。
現行表記を版面に固定すると、その未決を無視して確定させてしまう。

## 4. 状態による差分

| 変わり方 | 描き方 |
| --- | --- |
| 構造は同じで、要素の有無や文言だけが変わる | **版面は 1 つ**。「状態による差分」節に表で書く |
| 入力できる項目そのものが変わる | **版面を分ける**。見出しでモードを示す |

判断の基準は「**利用者が別の作業をしていると感じるか**」である。

かごが空かどうかは同じ作業の別状態なので 1 版面でよい。
`SCR-A-BOOK-EDIT` の「新規登録」「更新」「棚入れ」は、埋める項目が入れ替わり、
入口も違うため別の作業である。版面を 3 つ描く。

## 5. 共通フレーム

各画面の版面は、この枠の `本文領域` の中身だけを描く。

### 5.1 店頭

```
┌──────────────────────────────────────────────────────────────────────┐
│ Bob's Used Books    ‹ログイン時›注文  探す  ‹ログイン時›本を売る       │
│                     欲しい物  かご          利用者名 ‹管理者›管理画面  │
│                                                        ログイン/ログアウト│
├──────────────────────────────────────────────────────────────────────┤
│ ‹直前の操作が成功したとき› 通知バナー                                  │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│                            本文領域                                   │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

「注文」「本を売る」はログイン時のみ、「管理画面」は管理者のみ現れる。
利用者名は自分の住所（`SCR-ADDRESSES`）への導線を兼ねる。

### 5.2 管理

```
┌──────────────────────────────────────────────────────────────────────┐
│ Bob's Used Books   ダッシュボード  注文  買取  在庫  参照データ         │
│                                              利用者名  ログアウト      │
├──────────────────────────────────────────────────────────────────────┤
│ ‹直前の操作が成功したとき› 通知バナー                                  │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│                            本文領域                                   │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.3 共通部品

次の要素は [conventions.md](../conventions.md) が作法を定めている。
**版面には描くが、説明は書かない。** 画面固有の事情があるときだけ「配置の意図」に書く。

| 部品 | 版面での表し方 |
| --- | --- |
| 通知バナー | 共通フレームにあるので描かない |
| 確認ダイアログ | 本文の後に別枠で描く（§6 の例） |
| ページ送り | 一覧の上下に `‹ 1 2 3 ›` |
| 絞り込み帯 | 一覧の上に枠で囲んで置く |
| 検証メッセージ | 入力欄の直下に `⚠ メッセージ` |

## 6. 例

書式を示すための架空の画面である。実在の画面ではない。

````markdown
# SCR-EXAMPLE — 例示のための一覧画面

| 項目 | 内容 |
| --- | --- |
| 経路 | /Example |
| 定めるユースケース | [UC-CUST-99](../../use-cases/customer-browse.md) |
| フレーム | 店頭 |

## 版面

```
  例示の一覧                                          [ 新しく作る ]

  ┌─ 絞り込み ──────────────────────────────────────────────────┐
  │ 名前 [__________]  種別 [ すべて   v]   [ 絞り込む ] [ 解除 ] │
  └──────────────────────────────────────────────────────────┘

                                                     ‹ 1 2 3 ›
  ┌──────┬──────────────┬────────┬──────────────────────────┐
  │      │ 名前          │ 状態    │                          │
  ├──────┼──────────────┼────────┼──────────────────────────┤
  │  ▨   │ ある項目      │ 受付待ち│ ▸詳細  ‹受付待ちのみ›[受付]│
  │  ▨   │ 別の項目      │ 出荷済  │ ▸詳細                     │
  │ «同じ形の行が並ぶ»                                          │
  └──────┴──────────────┴────────┴──────────────────────────┘

  ‹1 件もないとき› 「まだ何もありません」  ▸ 探しに行く
```

## 配置の意図

- 状態は名前の右隣に置く。一覧を見る目的が「次に手を打つものを見つける」ことにあるため
- 操作は行の右端に集め、状態によって出し分ける

## 状態による差分

| 状態 | 版面の変化 |
| --- | --- |
| 受付待ち | 「受付」が現れる |
| 出荷済・取消済 | 操作は「詳細」だけになる |
````

## 7. 進め方

1. `customer/` から起こす。利用者が最初に触る順（`SCR-HOME` → `SCR-SEARCH` → …）に進める。
2. 1 枚ごとに、対応するユースケースの【Boundary】節と突き合わせる。
   **版面にあって Boundary にない要素が出たら、ユースケース側の記述漏れである。**
   ワイヤーフレームで足さず、ユースケースを直す。
3. `admin/` を起こす。
4. `SCR-` 単位で業務担当者と読み合わせる。
