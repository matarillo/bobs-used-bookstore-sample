# 外部連携（Integrations）

自分たちのシステムの **境界** と、その外にある依存先を定める。
**「どこまでが自分たちの責任で、何を外部に委ねるか」** を、顧客・チーム・AI が同じに理解するための文書である。
生成 AI は外部の契約を勝手に想像しがちなので、ここで固定して幻覚を防ぐ。

## 1. 何を書き、何を書かないか

外部システムごとに、**観測できる契約**と、**失敗したときの観測できる振る舞い**を書く。
内部の実装（クライアントの作り、リトライの仕組み）は書かない。それは設計層である。

| 項目 | 内容 |
| --- | --- |
| `EXT-` | 識別子 |
| 委ねること | 何を外部に任せるか |
| 契約 | 入出力の**参照**（プロトコル・API の公開文書へのリンク）。本文は写さない（[文書体系 §6.1](../README.md)） |
| 失敗時の見え方 | 外部が落ちた／遅い／拒否したとき、ユーザーに何が見えるか。`UC-` の異常系と一致させる |
| 要求側の含意 | コスト・データ共有・可用性リスクは `product/`（constraints・risks）を参照 |

開発時（Local プロファイル）は、すべての連携先がローカル実装に差し替えられる。
差し替えの構成は [design/architecture.md §3.1](../design/architecture.md) にある。

## 2. 一覧

| ID | 連携先 | 委ねること | 失敗時の見え方 |
| --- | --- | --- | --- |
| `EXT-AUTH` | Amazon Cognito | 本人確認・サインアップ・氏名とメールの管理・管理者グループの所属 | ログインできない。匿名で使える画面だけが使える |
| `EXT-IMG-STORE` | Amazon S3 ＋ CloudFront | 表紙画像の保管と配信 | 保管失敗は登録操作がエラー画面。配信失敗は画像だけ表示されない |
| `EXT-IMG-CHECK` | Amazon Rekognition | 表紙画像の適正判定 | 判定不能はエラー画面。「不適正」の判定は入力エラーとしてその場で伝わる |
| `EXT-CONFIG` | AWS Systems Manager Parameter Store ＋ Secrets Manager | 実行時構成と DB 資格情報 | 起動時に読めなければアプリが立ち上がらない（全画面到達不能） |
| `EXT-LOGS` | Amazon CloudWatch Logs | アプリケーションログの保管 | 利用者からは観測されない（ログの欠落のみ） |

## 3. 各連携先の契約

### EXT-AUTH — 本人確認

- **委ねること**: 本人確認、サインアップ、パスワード管理、氏名（名・姓）とメールアドレスの保持、
  `Administrators` グループの所属判定。**本システムはパスワードを預からない。**
- **契約**: OpenID Connect（認可コードフロー、Cognito Hosted UI）。
  本システムが受け取るのは、主体識別子（[用語集](../glossary.md) §7 の Sub）・利用者名・名・姓・グループである。
  主体識別子はドメインが顧客を特定する唯一の手段になる。
  ログイン成立のたびに氏名を取り込み、顧客を登録・更新する（[UC-CUST 前提](use-cases/customer-checkout.md)、
  氏名が画面から編集できない理由でもある——[Q-02](../product/open-questions.md)）。
- **失敗時の見え方**: 認証基盤に到達できない間はログイン操作が完了しない。
  未認証のまま使える画面（トップ・検索・書籍詳細・かご・欲しい物）はそのまま使える。
  認証が必要な画面はログイン要求へ誘導される（[NFR-SEC-02](non-functional.md)）。
- **要求側の含意**: 氏名・メールの保管場所が外部にあること → [constraints](../product/constraints.md)。

### EXT-IMG-STORE — 表紙画像の保管と配信

- **委ねること**: 表紙画像の原本の保管（非公開バケット）と、顧客・スタッフへの配信（CDN 経由の HTTPS）。
- **契約**: 保管は S3 API。配信は CloudFront のドメインに対する HTTPS GET のみ
  （バケットへの直接アクセスは拒否される）。書籍が保持するのは配信 URL である
  （論理型「外部資源参照」——[design/README §4.1](../design/README.md)）。
- **失敗時の見え方**: 保管に失敗すると、画像付きの書籍登録・更新（[UC-STAFF-14 / 15](use-cases/staff-catalog.md)）が
  エラー画面に落ちる。配信に失敗しても画面は表示され、画像だけが欠ける。
- **要求側の含意**: 配信ドメインは AWS 生成のものを使う（独自ドメインなし）。

### EXT-IMG-CHECK — 表紙画像の適正判定

- **委ねること**: アップロードされた表紙画像が公開に適するかの判定。
- **契約**: 画像 1 枚を渡し、適正／不適正の判定を受け取る。
  不適正の基準は次の 10 カテゴリのいずれかに該当すること——
  露骨な性的表現、性的示唆、暴力、視覚的に不快、侮辱的ジェスチャー、薬物、たばこ、酒、賭博、ヘイトシンボル。
  **画像なしは適正**として扱う。判定は書籍の登録・更新時のみ行われる（[UC-STAFF-14 / 15](use-cases/staff-catalog.md)）。
- **失敗時の見え方**: 「不適正」の判定は入力検証エラーと同じ作法でその場で伝わる
  （[conventions](conventions.md) の想定内の失敗 3 種の一つ）。
  判定サービス自体に到達できない場合はエラー画面に落ちる（[Q-07](../product/open-questions.md) の系）。
- **要求側の含意**: 判定基準は外部サービスの語彙をそのまま受け入れている（店独自の基準はない）。

### EXT-CONFIG — 構成と秘匿情報

- **委ねること**: 本番の実行時構成（認証・画像配信などのパラメータ）と、DB 資格情報の保管。
- **契約**: 起動時にパス `/BobsBookstore/` 以下のパラメータを読み込む。
  DB 資格情報は Secrets Manager の秘密から取得する（秘密の名前自体もパラメータで間接参照する）。
- **失敗時の見え方**: 起動時に読めなければ DB に接続できず、アプリは事実上起動しない。
  実行中の失敗は起こらない（起動時にのみ読む）。
- **要求側の含意**: 資格情報をコード・リポジトリに置かない（[NFR-SEC-05](non-functional.md)）。

### EXT-LOGS — ログの保管

- **委ねること**: アプリケーションログの保管と保持。
- **契約**: ログの送出のみ（片方向）。
- **失敗時の見え方**: 利用者からは観測されない。運用上はログが欠落する。

## 4. 存在しない連携先

**次の連携先は存在しない。** 規定がないことも仕様である（[文書体系 §9](../README.md)）。
AI はこれらの連携を勝手に想像してはならない。

| 連携先 | 現状 | 未決事項 |
| --- | --- | --- |
| 決済（`EXT-PAYMENT` に相当） | **ない**。注文の確定は支払を伴わず、代金の授受はシステムの外で行われる | [Q-28](../product/open-questions.md)、[ADR-0001](../product/decisions/ADR-0001-defer-online-payment.md) |
| 通知メール等（`EXT-MAIL` に相当） | **ない**。買取・注文の進行は画面でしか伝わらない | [Q-21](../product/open-questions.md)、[ADR-0002](../product/decisions/ADR-0002-defer-notifications.md) |
| 配送業者 | **ない**。追跡番号・配送業者・実出荷日を記録しない | [Q-23](../product/open-questions.md) |

## 5. 他の文書との関係

- 外部システムは [actors.md](../product/actors.md) にも **アクター**として現れる。
  そこでは「誰か・何の役割か」を、ここでは **観測できる契約と失敗**を持つ。
- `UC-` の Controller が外部を呼ぶときは、手順に契約を書き写さず **`EXT-` を参照**する。
- 外部障害時に守る品質（注文を失わない等）は [non-functional.md](non-functional.md) の `NFR-` に置く。
- どのフィーチャーがどの連携先を使うかの対応は [design/architecture.md §5](../design/architecture.md) にある。
