# Bob's Used Bookstore — ドメイン論理設計書

本書は、中古書店「Bob's Used Bookstore」のドメイン層をリバースエンジニアリングし、**ドメイン駆動設計 (DDD)** の語彙で再構成した論理設計書である。

## 0. 本書の位置づけ

### 0.1 目的

- **人間**が、このシステムが表現している業務（中古書籍の販売と買取）の構造とルールを、実装を読まずに理解できるようにする。
- **エージェント**が、変更要求を受けたときに「どの集約の、どの不変条件に触れるのか」を機械的に特定できるようにする。

### 0.2 スコープ

| 含む | 含まない |
| --- | --- |
| 集約・エンティティ・値の構造 | プログラミング言語の構文・型システム |
| 不変条件とビジネスルール | 永続化機構・O/Rマッピング・DBスキーマ |
| ドメインサービスとユースケース | 画面・API・認証基盤・クラウド構成 |
| ライフサイクルと状態遷移 | 非同期処理・並行制御の実装方式 |
| 読み取りモデル（統計・照会） | ライブラリ・フレームワーク固有の作法 |

本書は**論理設計レベル**であり、特定の実装技術を意図的に排除している。実装との対応が必要な場合のみ、付録 [15-traceability.md](15-traceability.md) を参照すること。

### 0.3 読み方

```
はじめて読む人      → 01 → 02 → 10 → 11
モデルを変更する人   → 02 → 該当する 03〜08 → 11 → 14
仕様を確認したい人   → 11（ルール一覧）→ 13（テストによる仕様）
実装に手を入れる人   → 14（課題）→ 15（対応表）
```

## 2. 記法

### 2.1 識別子の体系

本書の要素にはすべて安定した識別子を付与している。変更要求や課題報告では、この識別子で参照すること。

| 接頭辞 | 意味 | 例 |
| --- | --- | --- |
| `AGG-` | 集約 | `AGG-BOOK` |
| `INV-` | 不変条件（モデルが常に満たす条件） | `INV-BOOK-02` |
| `RULE-` | ビジネスルール（業務上の取り決め） | `RULE-ORDER-03` |
| `POL-` | ポリシー（差し替え可能な判断） | `POL-IMAGE-SAFETY` |
| `UC-` | ユースケース | `UC-SALES-05` |
| `RM-` | 読み取りモデル | `RM-BOOK-STATS` |
| `SPEC-` | テストで検証済みの仕様 | `SPEC-BOOK-01` |
| `ISSUE-` | 設計課題 | `ISSUE-07` |

### 2.2 論理型の語彙

実装上の型ではなく、業務的な意味を表す論理型を用いる。

| 論理型 | 意味 |
| --- | --- |
| 識別子 | 集約インスタンスを一意に指す値 |
| 参照 | 他の集約を識別子で指す（実体を含まない） |
| テキスト | 人間可読の文字列 |
| 金額 | 通貨単位を伴う数値。丸め規則はドメイン未定義 |
| 数量 | 0 以上の整数 |
| 日時 | 時点。基準タイムゾーンは [ISSUE-09](14-design-issues.md) を参照 |
| 年 | 暦年 |
| 真偽 | 二値 |
| 列挙 | 定義済みの値集合から 1 つ |
| 外部資源参照 | ドメイン外に保管された資源（画像など）の所在 |

### 2.3 必須・任意

| 記号 | 意味 |
| --- | --- |
| ● | 必須。生成時に必ず与えられる |
| ○ | 任意。未設定を許容する |
| ◇ | 派生。他の属性から計算される（保持しない） |

### 2.4 不変条件の強制レベル

DDD において不変条件は集約が守るべきものだが、現状のモデルでは強制されていないものがある。本書では両者を区別する。

| 記号 | 意味 |
| --- | --- |
| **[強制]** | 集約の振る舞いによって破れないことが保証されている |
| **[表明]** | モデル上そう意図されているが、破る操作が存在する |
| **[外部]** | 集約の外（呼び出し側）で守られることを前提としている |
| **[不成立]** | 守られるべきだが、モデルが守っておらず実際に破られる |

**[表明]**・**[外部]**・**[不成立]** は、モデルの弱点を示す。詳細は [14-design-issues.md](14-design-issues.md) にまとめている。

## 3. 本書の前提と限界

1. 本書は**現行実装から導出**したものであり、業務担当者が承認した仕様書ではない。実装に存在しないルール（例：買取価格の算定基準）は本書にも存在しない。
2. ドメイン層に明示されず、永続化層に委ねられている判断（例：「期限超過注文」の定義）は、**ドメイン未定義**として明示している。
3. 「あるべき姿」と「現状」を混ぜない。改善提案はすべて [14-design-issues.md](14-design-issues.md) に隔離している。03〜13 は現状の記述である。
