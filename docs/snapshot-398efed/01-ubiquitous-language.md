# 01. ユビキタス言語

ドメインエキスパート・設計者・実装者・エージェントが共有する語彙。**この表にない言葉をモデルに持ち込まない**、逆に**モデルの要素はこの表の言葉で呼ぶ**ことを原則とする。

## 1. 事業の中核概念

| 用語（和） | 用語（英） | 定義 |
| --- | --- | --- |
| 中古書店 | Bookstore | 顧客から中古書籍を**買い取り**、在庫として**販売**する事業。売りと買いの二方向の流れを持つことが本ドメインの特徴 |
| 書籍 | Book | 販売可能な状態で店舗の在庫に載っている一点。同一タイトルでも状態が異なれば別の書籍として扱う |
| 買取オファー | Offer | 顧客が「この本を買い取ってほしい」と店舗に申し出た内容。**まだ書籍ではない** |
| 顧客 | Customer | 書籍を買う人であり、同時に書籍を売る人でもある。両方の役割を 1 つの概念が担う |
| 店舗担当者 | Administrator | 在庫・買取・注文を管理する側の人。ドメインモデル上の実体を持たず、操作の主体としてのみ現れる |

## 2. 販売側の語彙

| 用語（和） | 用語（英） | 定義 |
| --- | --- | --- |
| 買い物かご | Shopping Cart | 購入意思のある書籍を一時的に集めた入れ物。**注文になるまでは何も確定しない** |
| かご項目 | Shopping Cart Item | かごの中の一行。書籍への参照と数量、および「買いたいか」の意思を持つ |
| 欲しい物リスト | Wish List | 買い物かごと**同一の入れ物の中にある、購入意思なしの項目群**。別の集約ではない |
| 購入意思 | Want To Buy | かご項目が「かご」に属するか「欲しい物リスト」に属するかを決める唯一の区別 |
| 相関識別子 | Correlation Id | 買い物かごを指す識別子。顧客が特定される前の匿名の来訪者にもかごを持たせるために用いる |
| 注文 | Order | 顧客が特定の配送先に対して書籍の購入を確定させたもの。**作成された時点で在庫が減る** |
| 注文明細 | Order Item | 注文に含まれる書籍 1 種と数量 |
| 小計 | Sub Total | 注文またはかごの税抜き合計 |
| 税 | Tax | 小計に対して課される額 |
| 合計 | Total | 小計と税の和 |
| 配送予定日 | Delivery Date | 注文が顧客に届く見込みの日 |
| 注文状態 | Order Status | 注文のライフサイクル上の位置。→ [11-invariants-and-rules.md](11-invariants-and-rules.md) |

## 3. 在庫の語彙

| 用語（和） | 用語（英） | 定義 |
| --- | --- | --- |
| 在庫数 | Quantity | その書籍を今いくつ販売できるか |
| 在庫あり | In Stock | 在庫数が 1 以上であること |
| 在庫僅少 | Low In Stock | 在庫数が**在庫僅少しきい値**以下であること。在庫切れも在庫僅少に含まれる（→ [ISSUE-01](14-design-issues.md)） |
| 在庫僅少しきい値 | Low Book Threshold | 在庫僅少と判定する境界値。現行は 5 |
| 在庫引き落とし | Reduce Stock Level | 注文成立に伴い在庫数を減らす操作 |

## 4. 買取側の語彙

| 用語（和） | 用語（英） | 定義 |
| --- | --- | --- |
| 買取価格 | Book Price | 顧客が希望する、または店舗が提示する買取額 |
| オファー状態 | Offer Status | 買取申込のライフサイクル上の位置。承認待ちから支払完了まで |
| 承認待ち | Pending Approval | 店舗担当者がまだ諾否を判断していない |
| 承認済／発送待ち | Approved | 店舗が買い取ると決め、顧客からの現物発送を待っている |
| 受領確認済 | Received | 現物が店舗に届いたことを確認した |
| 支払完了 | Paid | 顧客への支払が済んだ。買取取引の終端 |
| 却下 | Rejected | 買い取らないと決めた。買取取引の終端 |
| 講評 | Comment | 店舗担当者がオファーに付す所見 |

## 5. 分類の語彙

書籍と買取オファーは、いずれも同じ 4 つの軸で分類される。これらは**参照データ**として一元管理される。

| 用語（和） | 用語（英） | 定義 |
| --- | --- | --- |
| 参照データ項目 | Reference Data Item | 分類の選択肢 1 つ。種別と表示名からなる |
| 参照データ種別 | Reference Data Type | 選択肢がどの軸に属するか |
| 出版社 | Publisher | 書籍を出版した組織 |
| 状態 | Condition | 中古品としての傷み具合 |
| 書籍種別 | Book Type | 装丁や媒体の区分 |
| ジャンル | Genre | 内容による分類 |

> **注意**：「状態 (Condition)」は書籍の物理的コンディションであり、「注文状態 (Order Status)」「オファー状態 (Offer Status)」とは無関係である。日本語では衝突するため、本書では前者を必ず「コンディション」と読み替えられる文脈で用いる。

## 6. 顧客の語彙

| 用語（和） | 用語（英） | 定義 |
| --- | --- | --- |
| 主体識別子 | Sub | 顧客を外部の認証基盤から受け取った不変の識別子で指す値。ドメイン内では**顧客を照会する主キー的な役割**を持つ |
| 住所 | Address | 顧客に属する配送先。顧客は複数持てる |
| 有効フラグ | Is Active | 住所が利用可能かどうか |

## 7. 言葉の使い分けに関する約束

1. **「削除」を安易に使わない**：住所は有効フラグを持ち、注文はキャンセル状態を持つ。物理的な消滅と業務上の無効化を区別する。
2. **「カート」と「注文」を混同しない**：かごの中身は在庫を拘束しない。在庫が動くのは注文の瞬間だけである。
3. **「オファー」と「書籍」を混同しない**：オファーは書籍と酷似した属性を持つが、在庫でも商品でもない。オファーが書籍に転化する経路は現状のドメインに存在しない（→ [ISSUE-06](14-design-issues.md)）。
4. **「顧客」は買い手と売り手の両方**：買取をする人を別概念にしていない。これは意図的な単純化である。
