# 実験：独立した .html ファイルで版面を描く

[本書式](../README.md) §3.1 は「ASCII の罫線で描く。図の生成器を使わない」と定めている。
本書はその規約に対する 3 つ目の変更案である。

**閲覧はローカルを前提とする。** VS Code のプレビュー拡張、または外部ブラウザで開く。
GitHub 上では `.html` は描画されず、ソースが表示される（[§5.2](#52-失ったもの)）。

> **これは正ではない。** 版面の正は [customer/](../customer/) の各ファイルである。
> 採用する場合は README §3 を書き換え、本書は破棄する。

本書の版面は**実際にブラウザで描画して確認した**。構文だけを整えて描画を見ないと、
ボタンが 1 文字ずつ縦に折り返すような破綻を見落とす（実際に起きた）。

## 1. ファイル

```
EXPERIMENT-standalone/
  README.md            本書
  wireframe.css        共通の描画規約。寸法・色・書体はここにしか無い
  SCR-CHECKOUT.html    領域が 3 つある画面
  SCR-CART.html        表と、状態で入れ替わるフッタと、確認ダイアログ
  SCR-RESALE-NEW.html  入力が主体の画面
```

3 枚目を入れたのは、[Mermaid の実験](../EXPERIMENT-mermaid.md) で
**入力主体の画面が書けないことが決定打になった**ためである。同じ画面で比べる。

## 2. 設計判断：寸法をファイルで隔離する

[README §3.4](../README.md) は「寸法・色・書体・余白は定めない」と言う。
CSS が使える書式でこれをどう守るか。本実験の答えは**ファイルの分離**である。

| ファイル | 持つもの |
| --- | --- |
| `SCR-*.html` | 何が、どの順で、どのグループに、どの重みで並ぶか |
| `wireframe.css` | 寸法・色・書体・余白。**全画面で共通の描画規約** |

画面ファイルに `style` 属性を書かない。必要な見え方は共通語彙の側に足す。
これにより「この画面の版面」には寸法が一切現れず、§3.4 を**規律ではなく構造で**守れる。

これは §3.3 が「ヘッダを 25 画面で描き直さない」と言っているのと同じ理屈である。

**分けているのは寸法だけである。** 1 枚は自己完結し、[README §2](../README.md)「1 枚の構成」の
とおり、メタデータ・版面・配置の意図・状態による差分をすべて同じ `.html` に持つ。
YAML の前付けに当たるものは `<meta>` で表す。

## 3. 記法の対応

| 意味 | ASCII | この書式 | 表せるか |
| --- | --- | --- | --- |
| ボタン | `[ 保存 ]` | `<span class="btn">` | ○ |
| リンク | `▸ 詳細` | `<span class="link">` | ○ |
| 自由入力 | `[__________]` | `<span class="field">` | **○ 表示項目と明確に別物に見える** |
| 選択 | `[ 選択 v]` | `<span class="select">` | **○** |
| ラジオ・チェック | `(o) ( )` | `<span class="radio on">` | ○ |
| 画像 | `▨` | `<span class="img">` | ○ |
| 繰り返し | `« … »` | `<span class="repeat">` | ○ |
| 条件付き | `‹ … ›` | `<span class="cond">` | ○ |
| 領域 | 罫線 | `<section class="region">` | ○ 入れ子も効く |
| 列の重み | 罫線の長さ | `.u1`〜`.u8`（12 分割） | ○ |
| 縦の重み | 行数 | 見出し階層・余白 | ○ |
| 打ち消し | 無い | `<span class="oos">` | **○** |
| 確認ダイアログ | 本文の後に別枠 | `<div class="dialog">` | ○ |

**4 書式で唯一、記法表に「✗」が無い。**

## 5. 評価

### 5.1 得たもの

| 点 | 内容 |
| --- | --- |
| **入力欄が入力欄に見える** | `SCR-RESALE-NEW` が版面として成立する。Mermaid が描けなかった画面が描ける。自由入力・選択・金額欄の幅の違いも出る |
| **寸法を画面ファイルから追い出せる** | §2 のとおり。他の 3 書式にはこの性質が無い（ASCII は罫線の長さが版面に焼き付く） |
| **記法の穴が無い** | 打ち消し線も確認ダイアログも領域の入れ子も縦の重みも表せる |
| **描画が最も版面らしい** | 4 書式で、実際の画面に最も近い像が出る。読み合わせで「これでよい」と言いやすい |
| **共通フレームを CSS 側に置ける** | ヘッダ・通知バナーを一度書けば全画面に効く。§3.3 の懸念が構造的に消える |

### 5.2 失ったもの

| 点 | 内容 |
| --- | --- |
| **GitHub 上で読めない** | `.html` は描画されずソースが出る。**PR のレビューで版面を見られない**。差分レビューで画面を確認する運用は成立しない |
| **他文書への相互参照が片道になる** | 仕様層は `.md` が主体である。ブラウザで `.html` を開いてユースケースへのリンクを踏んでも、`.md` は描画されない。**ワイヤーフレームだけを別書式にすると、文書どうしの行き来が切れる** |
| **メタデータの表し方が他文書と揃わない** | YAML の前付けが使えず `<meta>` になる。[文書体系 §5.5](../../../README.md) の規約が書式ごとに二通りになり、`status` を機械的に集計する手段も分かれる |
| **原文が版面に見えない** | 4 書式で最も遠い。タグを読んで版面を思い描ける人はいない |
| **見え方が読む人の窓幅で変わる** | 実測で、窓を狭めると列見出しが折り返した。ASCII は誰が見ても同じ像である。**読み合わせで「同じものを見ている」保証が無い** |
| **モックアップに滑る** | CSS が使える以上、余白や字面を作り込む誘惑が常にある。共通 CSS への隔離は抑止になるが、最後は規律に依存する |
| **描画を見ないと壊れていても気づかない** | ボタンが 1 文字ずつ縦に折り返していた。ASCII なら原文の時点で分かる |

### 5.3 所見

**表現力は 4 書式で最高、文書としての性質は最低である。**

決め手は表現力ではなく、**どこで読み合わせるか**に尽きる。

| 読み合わせの場 | 適する書式 |
| --- | --- |
| ブラウザを一緒に見る／画面を投影する | **独立 .html**。他に選ぶ理由が無いほど良い |
| GitHub の PR で回覧し、差分で確認する | **ASCII**。.html は描画されない |
| 印刷して配る | ASCII または .html（印刷は .html の方が読める） |

なお **ASCII と .html を両方持つことはできない**。同じ版面が二か所にあることになり、
[文書体系 §6.1](../../../README.md)「同じ事実を二か所に書かない」に反する。
ASCII から .html は機械生成できないため、二重管理になる。**どちらかを選ぶ。**

## 6. 決めること

| 問い | 内容 |
| --- | --- |
| 読み合わせの場 | **これを先に決める。** ブラウザか、GitHub の PR か。書式の選択はここで決まり、他の比較項目は従属する |
| 独立 .html の採否 | 採るなら [README §3](../README.md) と、[文書体系 §5.5](../../../README.md) のメタデータ規約に `.html` の場合を書き足す |
| 採らない場合 | ASCII を維持し、打ち消し線と確認ダイアログを [README §3.2](../README.md) の記法表に足す |
| 実験の後始末 | 本書、[EXPERIMENT-html.md](../EXPERIMENT-html.md)、[EXPERIMENT-mermaid.md](../EXPERIMENT-mermaid.md) を破棄するか、判断材料として残すか |
